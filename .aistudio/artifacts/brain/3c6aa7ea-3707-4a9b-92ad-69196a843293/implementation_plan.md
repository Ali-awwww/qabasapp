# خطة عمل: حماية بيانات السحابة ومعالجة انقطاع الاتصال بذكاء 🛡️

## 1. تجربة المستخدم العادي (Seamless Offline Fallback):
- عند فشل الاتصال بالإنترنت أو عدم توفر السحابة:
  - لن تظهر أي شاشة خطأ أو بطاقات تشخيص تقنية للمستخدمين العاديين.
  - ينتقل التطبيق **تلقائياً** إلى مقاطع **وضع الأثر** والفيديوهات المخزنة محلياً في الكاش (`SilentReelStorageManager` + `cachedReels`).
  - عرض شريط علوي صغير ودود وجمالي يُخبر المستخدم بأنه يعمل في **"وضع الأثر (أوفلاين)"** مع إمكانية التصفح بسلاسة وبدون أي انقطاع.

---

## 2. تجربة المطور وحماية بيانات Supabase (Developer Diagnostic & Sanitization):
- **حصر شاشة التشخيص الفني:** لا تظهر بطاقة `ReelsDiagnosticCard` إلا إذا كان الحساب المسجل حساب مطور (`isDeveloper = true`)، وحتى للمطور تظهر مع خيار بسيط وواضح.
- **إخفاء وتشفير الروابط (Data Masking / Lock 🔒):**
  - استبدال الروابط الحساسة مثل `https://egkgygbvoeevakwkbvfu.supabase.co/rest/v1/...` بنص أمني مشفر: `[🔒 مسار السحابة محمي]`.
  - تنظيف رسالة الخطأ لتقتصر على السبب الصريح (مثلاً: `تعذر الاتصال بالشبكة (DNS / No Internet)`) بدلاً من إلقاء الاستعلام كاملاً.
- **تبسيط التقرير التشخيصي:**
  - عرض المؤشرات الثلاثية الهندسية بأناقة (زمن الاستجابة، رمز الحالة، حالة قاطع الحماية).
  - إظهار ملخص نظيف لحالة الخادم دون تعريض معمارية الجداول أو المفاتيح.

---

## 3. خطوات التنفيذ البرمجي:
1. تعديل `SupabaseServices.kt`: تنقية `userFriendlyMessage` و `errorMessage` عبر إزالة الروابط الخام واستبدال أسماء الجداول والمسارات برمز أمان.
2. تعديل `ReelsScreen.kt`:
   - توجيه المستخدم غير المطور فوراً لمقاطع وضع الأثر عند انقطاع الاتصال.
   - حصر ظهور `ReelsFailureDiagnosticScreen` في وضع المطور فقط.
   - تعديل `ReelsDiagnosticCard` لإخفاء الروابط واستبدالها بواجهة مشفرة برمز قفل.
3. فحص البناء والتحقق عبر `compile_applet`.
