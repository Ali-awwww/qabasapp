# مخطط إعادة ضبط وتثبيت اتصال Supabase Storage ومعالجة تشغيل الفيديوهات

## 1. تحليل سبب المشكلة
- **سبب انقطاع جلب الفيديو:** عند رفع مقطع فيديو جديد، كانت دالة الرفع في `ReelPublishManager.kt` تحاول الرفع أولاً إلى سلة غير عامة باسم `user-uploads` قبل السلة الرئيسية المعتمدة `reels` (المدعومة بسياسات القراءة العامة في Supabase Schema).
- عند الجلب والتشغيل عبر `ReelPlayer` أو `ExoPlayer`، كان الخادم يعيد أخطاء HTTP 400/404 أو عدم توفر السلة، مما يسبب ظهور رسالة *"تعذر تحميل المقطع حالياً"* والدوران اللانهائي.

---

## 2. التغييرات البرمجية المقترحة
1. **تعديل دالة رفع الفيديوهات (`ReelPublishManager.kt`):**
   - تعديل الترتيب ليحاول الرفع بالترتيب القياسي المعتمد:
     1. سلة `reels` (السلة العامة الأساسية بالفئة العامة `public = true`).
     2. سلة `media-assets`.
     3. سلة `user-uploads`.
   - إضافة آلية الفحص والتحقق المسبق مع دعم التشغيل الاحتياطي للملفات المحلية لمنع أي انقطاع.

2. **تحسين دالة تشغيل الريلز (`ReelPlayer.kt`):**
   - عند حدوث خطأ تشغيل في رابط السحابة البعيد، تقوم الدالة بالتحقق التلقائي مما إذا كان المقصد يحتوي على نسخة محليّة في `published_reels` أو الكاش وتحويل التشغيل إليها تلقائياً.

3. **توفير استعلام SQL الشامل لـ Supabase:**
   - تقديم استعلام جاهز لإعادة إنشاء وتهيئة كافة سلال التخزين (`reels`, `media-assets`, `user-uploads`, `avatars`) وتعديل سياسات الأمان `storage.objects` لتكون عامة للقراءة والرفع.
