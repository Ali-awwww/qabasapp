# خطة تنفيذ: عرض رقم إصدار التطبيق الحقيقي في تذييل الشاشة الرئيسية وفحص التحديثات

## الملخص العام
عرض رقم الإصدار الحقيقي للتطبيق ورقم البناء الفعلي (`BuildConfig.VERSION_NAME` و `BuildConfig.VERSION_CODE` المستخرجين من نظام أندرويد و Gradle) في التذييل السفلي (Bottom Footer) للشاشة الرئيسية دون أي محاكاة أو قيم ثابتة، مع إمكانية النقر على الشارة لإجراء فحص فوري للتحديثات عبر `UpdateManager` أو الانتقال لمركز التنزيلات والتحديثات.

---

## مراجعة قرارات المستخدم المؤكدة
> [!IMPORTANT]
> بناءً على إجابات المستخدم في الاستبيان:
> 1. **موقع شارة الإصدار**: في التذييل السفلي للشاشة الرئيسية (Bottom Footer of the Main Screen).
> 2. **صيغة النص**: الاسم ورقم البناء معاً بصيغة واضحة ومهنية (مثال: `v1.3.3 Build 102`).
> 3. **السلوك عند النقر**: النقر على الشارة يقوم بالتحقق الفوري من وجود تحديثات جديدة عبر `UpdateManager` مع إشعار المستخدم بالنتيجة وإتاحة الانتقال لمركز التنزيلات.

---

## 1. المعمارية وتدفق البيانات الحقيقية

```
┌─────────────────────────────────────────────────────────────┐
│                   Android Build System                      │
│      BuildConfig.VERSION_NAME (1.3.3)                       │
│      BuildConfig.VERSION_CODE (102)                         │
└──────────────────────────────┬──────────────────────────────┘
                               │ (استخراج حقيقي بدون محاكاة)
                               ▼
┌─────────────────────────────────────────────────────────────┐
│             Real App Version Resolver                       │
│   UpdateManager.getCurrentVersionName(context)              │
│   UpdateManager.getCurrentVersionCode(context)              │
│   Format: "v1.3.3 • Build 102"                              │
└──────────────────────────────┬──────────────────────────────┘
                               │
                               ▼
┌─────────────────────────────────────────────────────────────┐
│          Main Screen Footer Component                       │
│  [ 🚀 قَبَس v1.3.3 Build 102 • اضغط للتحقق من التحديثات 🔄 ] │
└──────────────────────────────┬──────────────────────────────┘
                               │ (عند النقر)
                               ▼
┌─────────────────────────────────────────────────────────────┐
│                 UpdateManager Flow                          │
│  1. إظهار مؤشر فحص خفيف (Checking for updates...)           │
│  2. استدعاء UpdateManager.checkForUpdate(context, force=true)│
│  3. إن وُجد إصدار أحدث: إشعار المستخدم + فتح مركز التنزيلات  │
│  4. إن كان التطبيق محدثاً: إشعار "أنت تستخدم أحدث إصدار"    │
└─────────────────────────────────────────────────────────────┘
```

## 2. تفاصيل واجهة المستخدم والتصميم (Cyber Footer Badge)

1. **التصميم البصري**:
   - تصميم شارة ناعمة ومحترفة (Subtle Cyber Pill) متناسقة مع هوية التطبيق.
   - خلفية شبه شفافة زجاجية خفيفة (`Color(0xFF0F172A).copy(alpha = 0.6f)`) بإطار ناعم (`GoldPrimary.copy(alpha = 0.25f)`).
   - خط **Cairo** الأنيق مع أرقام بخط **RobotoMono** أو خطوط أندرويد المتناسقة لتوضيح أرقام الإصدار.
   - أيقونة تحقق خفيفة أو وميض ينبض بنعومة يشير إلى حالة التحديث.
   - الالتزام الصارم بقانون تقليص الأحجام (UI Micro-scaling) ومساحة لمس مريحة (48dp).

2. **التكامل في الشاشات الرئيسية**:
   - دمج الشارة في تذييل الشاشة الرئيسية بأسلوبيها:
     - `QabasHomeScreen.kt` (الواجهة الرئيسية القياسية).
     - `SpatialCommandHomeScreen.kt` (واجهة القيادة السايبرانية SPATIAL_CYBER_HUD).
   - يتم تمرير إجراء `onViewDownloads` للانتقال السريع لمركز التنزيلات عند الرغبة.

---

## 3. خطة العمل المباشرة والتحقق البرمجي

- **الخطوة 1**: بناء مكوّن مشترك `AppVersionFooterBadge` يقرأ بيانات النسخة الحقيقية حصراً من `context.packageManager` و `BuildConfig`.
- **الخطوة 2**: تضمين المكوّن في نهاية محتوى التمرير للتذييل في كل من `QabasHomeScreen.kt` و `SpatialCommandHomeScreen.kt`.
- **الخطوة 3**: ربط حدث النقر بدالة `UpdateManager.checkForUpdate(context, force = true)` التزاماً بتنفيذ منطق حقيقي كامل مع إشعار للمستخدم `Toast` وحالة تحميل متجاوبة.
- **الخطوة 4**: تشغيل أداة التحقق والتجميع `compile_applet` لضمان صحة البناء وخلو الكود من أي أخطاء.
