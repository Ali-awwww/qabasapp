# مخطط تنفيذ حل مشكلة إدراج ريلز وفصل خيارات نشر المطور

## 1. تحليل المشكلة والحل المطلوب
- **سبب الخطأ `[SAVE_ROW]`:** عند محاولة إدراج مقطع في جدول `reels` بـ Supabase، يرفض الخادم العملية إما بسبب تفعيل سياسات الأمان RLS بدون السماح بـ `INSERT` للمستخدمين، أو لعدم تطابق أعمدة الجدول مع البيانات الممررة من التطبيق (`quality`, `tags`, `publish_at`, `expiry_at`, `ai_analysis`).
- **حل المشكلة:** إعداد استعلام SQL مكتمل لتعديل جدول `reels` وإنشاء جميع الأعمدة المطلوبة وتفعيل سياسات السماح بالإدراج والقراءة `RLS Policies` للجميع وللمطورين.
- **فصل خيارات النشر:** المطور سيشاهد في أسفل شاشة `ReelPublishScreen` زرين منفصلين للتأكيد والنشر:
  1. **الزر الأول:** 🎬 **نشر ريلز عادي للمجتمع** (ينشر المقطع كمقطع ريلز عادي يظهر في التغذية العامة للمستخدمين).
  2. **الزر الثاني:** ⚡ **حقن فيديو أوفلاين (لوضع الأثر)** (يحقن المقطع كـ `silent_seed` مخصص للعمل عند انقطاع الإنترنت وتجربة الأوفلاين).

## 2. التغييرات البرمجية المقترحة
- **شاشة `ReelPublishScreen.kt`:**
  - إضافة نمط تحديد نوع النشر للمطور (`isSilentSeed`).
  - استبدال التبديل الداخلي والزر الواحد بزرين منفصلين وأنيقين بنمط السايبر في أسفل الشاشة:
    - زر **نشر ريلز مجتمعي عادي** (أزرق نيون/تكواز).
    - زر **حقن فيديو صامت للأوفلاين** (ذهبي/أرجواني مخصص للمطور).
- **توفير استعلام SQL المباشر لـ Supabase:**
  - تقديم استعلام جاهز للنسخ والتشغيل في Supabase SQL Editor لمعالجة أذونات وأعمدة الجدول `reels`.

## 3. خطة التحقق والتعمير
- تشغيل `compile_applet` للتأكد من خلو المشروع من أي أخطاء تجميع.
