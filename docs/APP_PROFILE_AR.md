# الملف التعريفي الشامل لتطبيق قبس

> **قبس** هو استوديو عربي لصناعة المحتوى المرئي والقرآني والمعرفي، يجمع بين أدوات الإنتاج الإعلامي، والذكاء الاصطناعي، والمكتبة الإسلامية في تجربة واحدة مبنية لنظام Android.

## 1. بطاقة التعريف

| البند | التفاصيل |
|---|---|
| الاسم التجاري | قبس — استوديو قبس |
| المعرّف البرمجي | `com.qabas.app` |
| النوع | تطبيق Android أصلي |
| الإصدار الحالي | `1.2.1` — الإصدار البرمجي `3` |
| الحد الأدنى للنظام | Android 7.0 / API 24 |
| النظام المستهدف | Android API 36 |
| لغة التطوير | Kotlin |
| واجهة المستخدم | Jetpack Compose وMaterial 3 |
| اتجاه المنتج | عربي، إبداعي، قرآني، مدعوم بالذكاء الاصطناعي |
| المستودع | [alippappa7-maker/qabas_studio](https://github.com/alippappa7-maker/qabas_studio) |

## 2. الرؤية والرسالة

### الرؤية
أن يكون قبس مساحة موحّدة تمكّن صانع المحتوى من تحويل الفكرة إلى مادة مرئية أو صوتية أو معرفية جاهزة للنشر، مع الحفاظ على الهوية العربية والقيمة الإسلامية.

### الرسالة
تقليل الوقت والتعقيد بين **الفكرة، والإعداد، والإنتاج، والمراجعة، والنشر** من خلال أدوات واضحة، وذكاء اصطناعي مساعد، ومحتوى إسلامي موثوق قدر الإمكان.

### المبادئ

- **المعنى قبل الزخرفة:** التقنية تخدم الرسالة ولا تستبدلها.
- **الوضوح:** إظهار حالة العملية، ومصدر البيانات، وحدود الأداة عند الحاجة.
- **الأمان:** عدم تضمين المفاتيح السرية في المصدر، وتقليل الصلاحيات المطلوبة.
- **الخصوصية:** الفصل بين إعدادات المستخدم وبيانات الخدمة، وتجنب جمع ما لا يلزم.
- **الإتقان:** توفير مسار إنتاج قابل للمراجعة وإعادة الاستخدام.
- **العربية أولاً:** واجهة ومحتوى وتجربة استخدام مناسبة للمستخدم العربي مع قابلية التوسع.

## 3. لمن صُمّم التطبيق؟

- إنتاج الفيديوهات القصيرة وReels.
- التقاط الصور والفيديو من الكاميرا.

- استخراج المقاطع من الوسائط.

### ب. الذكاء الاصطناعي

- مساعد محادثة للمساعدة في التخطيط والكتابة.

## 6. البنية التقنية

### طبقة العرض

- Kotlin وJetpack Compose.
- Material 3 ومكونات تصميم مشتركة في `QabasStudioSharedComponents` و`QabasUx`.
- شاشات Compose منفصلة حسب المجال مع مكونات قابلة لإعادة الاستخدام.
- دعم الخطوط العربية والموارد المحلية.

### طبقة الحالة والتنقل

- `AppNavigation` مسؤول عن الانتقال بين المسارات.
- ViewModels وخدمات الحالة للتدفقات طويلة العمر.
- حفظ تلقائي لمساحات العمل.
- حالات تحميل ومعالجة ومراجعة وتشخيص ظاهرة للمستخدم.

### طبقة البيانات والتخزين

- Room للتخزين المحلي وقاعدة البيانات.
- Firebase Firestore للبيانات السحابية عند تفعيل الخدمة.
- Supabase Auth وPostgREST وStorage وFunctions.
- خدمات تخزين مؤقت للصور والفيديو.
- `UserPreferencesManager` لتفضيلات المستخدم.
- نماذج Kotlin مخصصة للبيانات والمشاريع والوسائط.

### طبقة الوسائط والمعالجة

- Media3 للتشغيل.
- CameraX للكاميرا والفيديو.
- FFmpeg Kit للمعالجة والتحويل.
- OpenCV للتحليل والمعالجة البصرية.
- Coil لتحميل الصور.
- محركات محلية للفيديو والصور والصوت والتصدير.

### طبقة الذكاء الاصطناعي والاتصالات

- Firebase AI / Gemini.
- Retrofit وOkHttp للاتصالات.
- Kotlin Serialization وMoshi للتحويل بين JSON والنماذج.
- خدمات بوابة مثل `PlatformGatewayClient` و`GatewayAiService`.
- نماذج محلية اختيارية عبر ONNX وLlama.cpp.
- خدمات تحويل النص إلى صوت مثل Kokoro عند توفر النموذج.

## 7. تدفق العمل النموذجي

1. يفتح المستخدم قبس ويسجل الدخول أو يتابع كزائر بحسب سياسة التطبيق.
2. ينشئ مشروعاً أو يصف فكرته في نموذج الفكرة.
3. يختار نوع المخرج: فيديو، صورة، صوت، نص، أو محتوى إسلامي.
4. يقترح المساعد الذكي الهيكل والنص والمشاهد والوسوم.
5. يراجع المستخدم المحتوى ويضيف الوسائط أو يسجلها.
6. ينفذ التطبيق المعالجة المحلية أو يرسل المهمة إلى الخدمة المناسبة.
7. يراجع المستخدم النتيجة في شاشة المراجعة.
8. يحفظ المشروع تلقائياً، ثم يصدّر أو يجدول النشر.
9. يتابع الأداء من خلال الإحصاءات وسجل العمليات.

## 8. الأمان والخصوصية

- تُدار الأسرار من خلال Gradle Secrets Plugin وملف `.env` المحلي، ولا ينبغي رفع `.env` أو مفاتيح الإنتاج إلى Git.
- ملف `.env.example` هو المرجع للمتغيرات المطلوبة دون قيم سرية.
- مفاتيح API قابلة للإدارة من خلال شاشات مخصصة مع التحقق من صلاحيتها.
- استخدام Firebase App Check عند تهيئته في بيئة البناء.
- المصادقة مدعومة عبر Firebase Auth وSupabase Auth وGoogle Credentials بحسب المسار.
- الصلاحيات المطلوبة يجب أن تكون مرتبطة بميزة واضحة: الكاميرا، الميكروفون، التخزين/الوسائط، والإشعارات عند الحاجة.
- لا تُعامل مخرجات الذكاء الاصطناعي كمصدر شرعي نهائي؛ يجب عرض تنبيه المراجعة عند المحتوى الديني الحساس.
- يجب إخفاء المفاتيح في السجلات ورسائل الأخطاء، وتجنب تسجيل النصوص الخاصة أو الوسائط الأصلية دون ضرورة.

للتفاصيل التشغيلية الخاصة بالمفاتيح راجع [SECURE_PLATFORM_KEYS.md](SECURE_PLATFORM_KEYS.md).

## 11. الاختبارات والجودة

- اختبارات الوحدة في `app/src/test`.
- اختبارات الأجهزة في `app/src/androidTest`.
- اختبار واجهات Compose باستخدام Compose UI Test.
- اختبارات لقطات الشاشة عبر Roborazzi حيث تُستخدم.
- فحص مسار الدخول، إنشاء المشروع، الحفظ التلقائي، المعالجة، التصدير، القراءة القرآنية، وتشغيل الصوت قبل الإصدار.
- اختبار حالات انقطاع الشبكة، غياب المفاتيح، انتهاء الحصة، رفض الصلاحيات، وفشل الخدمة.
- التحقق من RTL، أحجام الخطوط، TalkBack، والتنقل بلوحة المفاتيح/إمكانية الوصول حيث ينطبق.

## 12. إرشادات التطوير

- ضع منطق المجال في خدمة أو ViewModel، ولا تضع طلبات الشبكة الثقيلة داخل Composable.
- اجعل العمليات الطويلة قابلة للإلغاء واعرض تقدمها للمستخدم.
- استخدم النماذج الموجودة قبل إضافة نماذج مكررة.
- حافظ على تسمية Kotlin الحالية: `PascalCase` للأنواع و`camelCase` للدوال والخصائص.
- افصل واجهات الإدارة والتشخيص عن تجربة المستخدم العادية عبر الحماية والصلاحيات.
- أضف النصوص القابلة للترجمة إلى موارد `strings.xml`، مع توفير العربية في `values-ar`.
- لا تضف أسراراً أو بيانات مستخدم حقيقية إلى المصدر أو الاختبارات.
- عند تعديل ميزة، حدّث هذا الملف إذا تغيّر مسارها أو اعتمادها أو صلاحياتها.
- استخدم Beads (`bd`) لتتبع المهام في بيئة التطوير وفق تعليمات المشروع.

## 13. حدود معروفة ومسؤوليات المستخدم

- توفر بعض الميزات يعتمد على الإنترنت، ومفاتيح الخدمة، وحصة المزود، وحالة الحساب.
- جودة النتائج المولدة تختلف باختلاف النموذج والطلب والمدخلات.
- المعالجة المرئية والصوتية قد تستهلك مساحة وبطارية وذاكرة كبيرة.
- مشاركة أو نشر المحتوى مسؤولية المستخدم، ويجب احترام حقوق النشر والخصوصية.
- المحتوى القرآني والحديثي يحتاج إلى مراجعة المصدر قبل النشر أو الاستدلال.
- يجب عدم اعتبار التطبيق بديلاً عن أهل العلم أو الاستشارة المتخصصة.

## 14. قاموس مختصر

- **قبس:** اسم المنتج، ويرمز إلى فكرة أو معرفة قابلة للمشاركة.
- **الاستوديو:** مساحة إنشاء وتحرير وإخراج المحتوى.
- **الوكيل:** عملية ذكاء اصطناعي متخصصة تنفذ خطوة من خطوات الإنتاج.
- **المشروع:** حاوية تجمع النصوص والوسائط والإعدادات والمخرجات.
- **البوابة:** طبقة توحّد الاتصال بخدمات الذكاء الاصطناعي أو المنصات.
- **طبيب التطبيق:** أدوات فحص وتشخيص لحالة التطبيق والخدمات.
- **مركز الحسنات:** مساحة تحفيزية مرتبطة بالمحتوى الإسلامي والمكافآت داخل المنتج.

## 15. معيار اكتمال الميزة

تُعد الميزة جاهزة عندما:

- تعمل في المسار الطبيعي ومسارات الخطأ الأساسية.
- تتعامل مع التحميل والفشل والإلغاء وإعادة المحاولة.
- تحفظ البيانات بالطريقة المناسبة محلياً أو سحابياً.
- لا تكشف الأسرار أو البيانات الحساسة في السجلات.
- تدعم العربية واتجاه RTL عند عرضها للمستخدم العربي.
- تملك اختباراً مناسباً أو تحققاً يدوياً موثقاً.
- تحدّث التنقل، الموارد، الوثائق، والصلاحيات عند الحاجة.
